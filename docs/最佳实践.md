# NanoHarness 开发者最佳实践

NanoHarness 是从零手写的轻量级多智能体编排引擎，不依赖 LangChain/LangGraph。本指南覆盖工具编写、技能定义、行为测试和 MCP 集成四个核心环节，所有示例均来自真实代码模式。

---

## 编写工具

### 函数签名

所有工具函数遵循统一契约：接收 `tool_input: dict` 和 `_ctx: Any`，返回 `ToolResult`。

```python
from core.tool_executor import ToolResult, ToolResultStatus

def translate_text(tool_input: dict, _ctx: Any) -> ToolResult:
    text = tool_input.get("text", "").strip()
    target_lang = tool_input.get("target_lang", "en").strip()

    if not text:
        return ToolResult(
            status=ToolResultStatus.FAILURE,
            content="缺少必填参数 text",
            error_code="empty_input",
            next_action_hint="请提供要翻译的文本",
        )

    try:
        result = _do_translate(text, target_lang)
        return ToolResult(
            status=ToolResultStatus.SUCCESS,
            content=result,
            next_action_hint="翻译完成，可继续处理或直接回复用户",
        )
    except TranslationError as exc:
        return ToolResult(
            status=ToolResultStatus.FAILURE,
            content=str(exc),
            error_code="translation_failed",
            next_action_hint="可尝试更换目标语言或简化输入文本",
        )
```

### 工具定义（JSON Schema）

工具定义与函数分开声明，供 LLM 读取：

```python
TRANSLATE_TOOL_DEF = {
    "name": "translate_text",
    "description": "将文本翻译为指定语言",
    "input_schema": {
        "type": "object",
        "properties": {
            "text":        {"type": "string", "description": "待翻译的原文"},
            "target_lang": {"type": "string", "description": "目标语言代码，如 en/zh/ja"},
        },
        "required": ["text"],
    },
}
```

### 异步工具

工具函数可以是协程，ToolExecutor 通过 `asyncio.iscoroutine` 自动处理，无需额外配置：

```python
async def fetch_url(tool_input: dict, _ctx: Any) -> ToolResult:
    url = tool_input.get("url", "").strip()
    if not url:
        return ToolResult(status=ToolResultStatus.FAILURE, content="缺少 url", error_code="empty_input")

    async with aiohttp.ClientSession() as session:
        async with session.get(url) as resp:
            body = await resp.text()
    return ToolResult(status=ToolResultStatus.SUCCESS, content=body[:4000])
```

### ToolContext 修改

`ToolContext` 是 frozen dataclass，**不能直接赋值**，用 `dataclasses.replace`：

```python
from dataclasses import replace
from core.context import ToolContext

# 错误：ctx.user_id = "new_id"  → FrozenInstanceError
# 正确：
updated_ctx = replace(ctx, user_id="new_id")
```

## 编写技能

技能文件放在 `skills/` 目录，支持 TOML 和 Markdown frontmatter 两种格式。

### TOML 格式

```toml
# skills/researcher.toml
name        = "researcher"
description = "网络研究员，负责信息检索与摘要"
tools       = ["web_search", "current_datetime"]
tier        = "T2"
capabilities = ["search", "research", "summarization"]

system_prompt_patch = """
你是一名专业研究员。
- 每次搜索前先明确关键词范围
- 搜索结果超过 3 条时，优先选取最新来源
- 输出摘要不超过 300 字，附原始来源链接
"""
```

### Markdown frontmatter 格式

```markdown
---
name: analyst
description: 数据分析师，处理结构化数据与统计计算
tools: [calculator, web_search, file_reader]
tier: T2
capabilities: [analysis, statistics, data_processing]
---

你是一名数据分析师。
- 收到数据集时先检查空值和异常值
- 统计结果保留两位小数
- 输出结论时附上置信度说明
```

### capabilities 路由

`capabilities` 列表决定 Supervisor 能否将任务路由到该技能。**不能为空**，否则按能力标签匹配时该技能不可见：

```toml
# 正确
capabilities = ["search", "research"]

# 危险：Supervisor 无法路由
capabilities = []
```

## 测试 Agent

### 行为指纹测试

使用 `tests/behavioral/fingerprint.py` 提供的 `run_and_fingerprint` + `BehaviorConstraint` 组合验证 agent 行为：

```python
from tests.behavioral.fingerprint import (
    BehaviorFingerprint,
    BehaviorConstraint,
    run_and_fingerprint,
)

async def test_researcher_uses_search():
    fp = await run_and_fingerprint(
        prompt="帮我查找 2024 年中国 AI 政策的最新动态",
        provider="anthropic",
        tools=[web_search_fn, current_datetime_fn],
        tool_defs=[WEB_SEARCH_DEF, CURRENT_DATETIME_DEF],
    )

    BehaviorConstraint(
        must_execute_tools={"web_search"},
        must_not_execute_tools={"file_writer"},  # 不应写文件
        call_count_min=1,
        call_count_max=5,
    ).assert_satisfied(fp)
```

### 多工具顺序约束

如需验证工具调用顺序（如先查询再计算）：

```python
BehaviorConstraint(
    must_execute_tools={"web_search", "calculator"},
    call_count_min=2,
    call_count_max=6,
).assert_satisfied(fp)

# 单独检查调用顺序（使用 fp.tool_calls 列表）
tool_names = [c.name for c in fp.tool_calls]
assert tool_names.index("web_search") < tool_names.index("calculator"), \
    "应先搜索后计算"
```

### run_turn 的正确用法

`NanoCore.run_turn()` 是 **async generator**，必须用 `async for` 迭代，不能 `await`：

```python
# 错误：result = await core.run_turn(msg)  → TypeError

# 正确：
async for event in core.run_turn(msg):
    if event.type == "text":
        print(event.content)
    elif event.type == "tool_use":
        print(f"调用工具：{event.name}")
```

## 常见陷阱

| 陷阱 | 现象 | 修法 |
|------|------|------|
| 工具函数内 `raise` 异常而不返回 `ToolResult.FAILURE` | LLM 收不到错误信息，无法恢复，对话卡住或乱跑 | 所有异常用 `try/except` 包裹，返回 `ToolResult(status=FAILURE, error_code=..., next_action_hint=...)` |
| 直接给 `ToolContext` 字段赋值 | `FrozenInstanceError` 运行时崩溃 | 改用 `dataclasses.replace(ctx, field=new_val)` |
| `await core.run_turn(msg)` | `TypeError: object async_generator can't be used in 'await' expression` | 改为 `async for event in core.run_turn(msg)` |
| `next_action_hint` 留空或过于模糊 | 工具失败后 LLM 无方向，可能无意义重试同一工具 | 写明下一步建议，如 `"参数格式不对，请改用 ISO 8601 日期格式"` |
| `capabilities` 列表为空 | Supervisor 按能力标签路由时找不到该技能，任务被丢弃或报错 | 至少填写 1 个能力标签，与任务描述匹配 |
| MCP 工具名拼写错误（单下划线） | 工具调用静默失败，LLM 收到 unknown tool 错误 | MCP 工具名格式固定为 `{server}__{tool}`（双下划线），不可自定义 |
| 在 `denied_tools` 列表里用错工具名 | 本想禁用的工具仍然可用，安全限制失效 | 工具名必须与 tool def 的 `name` 字段完全一致，包括大小写 |

## MCP 集成

### 配置 McpClient

在 `nanoharness.toml`（或代码中）配置 MCP 服务器，每个服务器对应一个命名空间：

```toml
# nanoharness.toml.example 片段
[mcp.servers.filesystem]
command = "npx"
args    = ["-y", "@modelcontextprotocol/server-filesystem", "/tmp/workspace"]

[mcp.servers.github]
command = "npx"
args    = ["-y", "@modelcontextprotocol/server-github"]
env     = { GITHUB_TOKEN = "${GITHUB_TOKEN}" }
```

### 工具命名规则

MCP 工具名自动生成为 `{server}__{tool}`（双下划线），无法自定义：

```python
# filesystem 服务器的 read_file 工具 → "filesystem__read_file"
# github 服务器的 search_repos 工具 → "github__search_repos"

# 在技能中引用 MCP 工具：
# skills/dev_assistant.toml
tools = ["filesystem__read_file", "filesystem__write_file", "github__search_repos"]
```

### AsyncExitStack 生命周期

McpClient 使用 `AsyncExitStack` 管理连接生命周期，需在 `async with` 块内使用：

```python
from mcp.client import McpClient

async def main():
    async with McpClient(config) as client:
        tools = await client.list_tools()           # 获取所有工具定义
        result = await client.call_tool(
            "filesystem__read_file",
            {"path": "/tmp/workspace/data.json"},
        )
        print(result.content)
    # 退出 with 块后连接自动关闭
```

### denied_tools 动态限制

通过 `denied_tools` 在运行时禁止特定工具，适合多租户或权限分级场景：

```python
from core.nano_core import NanoCore

core = NanoCore(
    tools=all_tools,
    tool_defs=all_tool_defs,
    denied_tools={"filesystem__write_file", "github__delete_repo"},  # 只读模式
)

async for event in core.run_turn("帮我分析这个仓库的结构"):
    ...
```
